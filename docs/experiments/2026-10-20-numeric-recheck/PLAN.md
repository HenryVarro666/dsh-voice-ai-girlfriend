# 数字疑点、长尾复核与默认/仅向量自动对照

2026-10-20运行前冻结。用户明确要求执行无评分路线。本轮生产保持ICL、全文预填、chunk4、temperature0.9、repetition1.05，裁剪关闭；不采用1.15、不改生产包或配置、不重启，不增加识别器或下载模型。

## 假设与顺序

1. 同一PCM的110022→10022可能来自识别波动：原始疑点20次STT；同seed原始数字输入控制5次，5.413秒长尾样本5次。顺序固定随机交错。出现多种结果时保留不确定归因，不将多数票作为发音真值。
2. 长尾可能是模型生成而非写WAV或HTTP补零：在apex重算未改的PCM及原始生成统计，检查帧数/自然EOS，随后默认同文本/seed重放，并核对WAV哈希和段尾。阈值1/3/10/33/99/328只作诊断，不裁剪。
3. ICL条件影响静音生成：独立模型仅切`xvec_only`，同文本/seed随机配对；同时检查数字内容是否出现新疑点，不以速度抵消内容退化。

先完成同PCM30次复核，再对现有盲听64条音频各重复STT3次（192次，不重新合成），覆盖重复词、长句、轻声词及结尾。后者只做内容回归，不代替音色或韵律评分。

## 新生成的冻结对照

[cases.json](cases.json)固定2条诊断编号和6条新编号/日期时间。诊断seed4409/5519/6619，各模式6条共12条；新输入seed7703/8803/9901，各模式18条共36条，总48条。使用明确中文读法，保持数字规范化规则不变，只比较ICL和向量，不重跑原先48条阿拉伯数字/中文读法基线。

两阶段分别沿用runner的固定交错seed20261022/20261023；每模式2次预热。token上限沿用handler估算，每条记录有效采样参数、声学码哈希、原始/PCM块时序、前导/段尾、EOS/上限与生成错误。额外将48份新PCM各重复STT3次，另保留生成runner自带的一次识别，不混成独立样本。

## 统计与边界

- 编号、日期、时间用现有修正后的严格字段核对器，match/mismatch/unparsed分开；三次全匹配、至少一次匹配、结果变化、请求失败分别列出。对每份固定PCM按哈希绑定转写，不把识别成功次数当成独立TTS样本。
- 默认稳定全匹配而向量出现非匹配的配对列新增疑点；同PCM转写波动时无法确定TTS错误，不抹掉差异。现有64条用字符检查仅做筛查，不替代听检，失败均保留。
- 诊断与新输入分开报告，所有分母含失败。小样本不提供稳定p95、显著性或总体错误率。首声从handler调用到幅度≥328的PCM块返回，总生成到耗尽及CUDA同步；都不含后续ASR/HTTP/DSH/LLM/浏览器/硬件，不是完整说完到首声或严格冷启动。
- 模型加载前空闲≥9000MiB、利用率≤20%、Ollama为空；加载后至少1500MiB空闲；每条前后查新GPU PID，出现则保留并退出自有进程。STT重放也记录GPU进程，不停止外部任务。开始/结束核对配置、bridge、插件哈希和原服务/health。
- 不因自动匹配宣布音色、韵律或天然轻声无退化，不因单个ASR疑点自动要求用户填32对。保留独立候选，不部署。本轮不执行完整DSH或取消/队列测试。

# 生成端长尾诊断：重复惩罚有局部收益，暂不部署

2026-10-20，apex RTX 5080 16 GB；生产同款 Qwen3-TTS-12Hz-0.6B-Base、faster-qwen3-tts 0.5.4、speech-to-speech 0.2.10，原参考音色、chunk_size=4。本轮只运行独立模型进程，没有修改生产代码、依赖或配置。

## 结论

可以从生成端改善已知长尾。重复惩罚从默认1.05调到1.15，在已知异常seed25上将PCM末尾低幅度区从5355.5ms降到79.1ms，声学帧113→23，仍由模型自行采样EOS结束。没有增加尾部裁剪或缩短token上限。原handler已有的前导静音处理保持原样，原始模型输出另行测量。

但这还不是可靠修复：新文本/新seed中两组都没有超过1秒的尾部，候选没有总体提速，转写有一条改善、一条退化。未进行人工回听，不能证明轻声、韵律、重复词和插话行为不受影响。决定保留实验候选，不部署；幅度裁剪继续关闭。

## 范围、样本与计时

按[事先冻结协议](PLAN.md)完成48条诊断（4文本×3seed×4策略），选出一个候选后另做24条新文本对照；额外2条关闭EOS追踪的基线控制，共74条有记录输出，另有2次不计分预热。没有失败输出被剔除。全部WAV与逐字转写留在apex：`~/voice-ai/experiments/20261020-generation-end/main-01/`。

- 只改变采样温度、重复惩罚或第一码本EOS logit；每条实际生成参数已记录。handler上限配置1536，但其内置文本长度估算使本集合各条实际上限均为360，所有策略相同。
- 逐步记录第一码本EOS概率（mask、温度、top-k之后）和实际是否采样，区分自然结束与撞上限。记录本身有开销，不把此计时当成生产HTTP表现。
- 首有声PCM：从调用handler生成到第一个绝对PCM幅度至少328的块返回；生成总时间：从调用到生成器耗尽并完成CUDA同步。均不含后续EOS统计、FunASR转写、LLM或浏览器播放，不是“用户说完到首声”，也不是严格冷启动。
- 段尾为最后一个绝对幅度至少99/32768的PCM样本到输出末尾的时长；原始float输出阈值0.003。这只是诊断指标，不能判断低幅度部分是否有人声。全程不据此裁剪。
- 模型在预热后测试；等待其他Ollama模型自然卸载才启动，未主动卸载他人模型。独立加载约2.704秒，显存增加约3627MiB，不与LLM生成做并发对照。

## 已知异常的生成证据

同句“好呀，我们开始吧。”：

| 样本与策略 | 原始前导低幅度 | PCM段尾 | 帧数 / 上限 | 首有声PCM到达 | 生成结束原因 |
|---|---:|---:|---:|---:|---|
| seed25 默认 | 1952.8ms | 5355.5ms | 113/360 | 612.1ms | EOS |
| seed25 repetition1.15 | 353.9ms | 79.1ms | 23/360 | 182.6ms | EOS |
| seed25 EOS+1 | 1952.8ms | 715.5ms | 55/360 | 614.5ms | EOS |
| seed16 默认 | 4573.3ms | 157.0ms | 76/360 | 1219.8ms | EOS |
| seed16 repetition1.15 | 298.6ms | 24.3ms | 21/360 | 182.9ms | EOS |
| seed16 EOS+1 | 4573.3ms | 157.0ms | 76/360 | 1221.4ms | EOS |

seed25默认最后一步EOS概率约95.50%，此前一步约53.43%但未被采样；不是这个样本一直没有EOS、最终撞token上限。EOS偏置改变了终止路径，重复惩罚则连前导生成路径也改变了。不能据此断言某个静音token就是唯一根因：第一码本重复惩罚会改变全部重复声学token的概率，可能同时影响真实语音。

关闭EOS追踪的两个控制样本与有追踪基线帧数、PCM前后时长相同；seed16首有声1236.4/1219.8ms、总生成1539.7/1524.3ms，seed25首有声611.4/612.1ms、总生成2240.6/2232.1ms。两条不能估计稳定追踪开销，但未观察到原异常由追踪新造出来。

## 独立新文本验证：每组12条

| 指标 | 默认1.05 | 候选1.15 |
|---|---:|---:|
| 自然EOS / 撞上限 | 12 / 0 | 12 / 0 |
| >1秒尾部 | 0 | 0 |
| 尾部总时长 / 最大值 | 3.028s / 654.1ms | 3.012s / 601.4ms |
| 首有声PCM中位 | 101.0ms | 104.4ms |
| 生成总时间中位 | 823.8ms | 827.8ms |
| 去标点转写精确匹配 | 9/12 | 9/12 |
| 字符编辑总数 | 3 | 3 |
| 末4字转写匹配 | 9/12 | 10/12 |

配对字符错误有1条改善、1条退化、10条不变。基线三条把“轻声”识别为同音“轻生”；候选其中一条恢复，但另一个样本把句首“请”识别为“起”。未人工听音，不能判定这些全是ASR问题或全是TTS问题。文本里写“轻声”不等于生成了经人工确认的弱声负例，尾4字匹配也不是轻声无损证明。

本组尾部总时长只少15.4ms，首声中位慢3.4ms；不宣称一般延迟改善、显著收益或稳定p95。诊断种子是既有异常样本，不能拿其大幅收益替代新文本表现。

## 更可靠的下一步

优先继续验证受支持的重复惩罚参数，而不是上线EOS硬阈值或按文本长度强制截断。下一组需冻结更多新文本与seed，重点包含叠词、重复数字/日期、中英混合和自然轻声结尾；对ASR差异与异常段人工回听，检查尾词和韵律。生成参数改变后需单独验插话取消，不由旧流式取消测试代替。

若仍出现静音循环，保留EOS/声学token诊断，区分“模型尚未认为结束”和“EOS已有竞争力但持续未采样”。再考虑有明确文本完成证据的终止策略或模型训练；单凭EOS概率或低能量都可能提前截断，当前没有实现或验证这种停止器。音色参考条件的消融也可做，但会同时改变音色与韵律，须另设控制，不能与本轮参数结果混算。

额外发现：speech-to-speech安装版本CUDA克隆分支未转发通用`gen_kwargs`，只改此配置可能没有生效。本实验在独立进程包装模型方法并记录真正收到的实参；没有趁机修生产库。未来接入前必须补参数传递契约与默认关闭的实验开关。

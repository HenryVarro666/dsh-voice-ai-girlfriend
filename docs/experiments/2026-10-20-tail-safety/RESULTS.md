# 流式尾部保护安全性对比结果

2026-10-20，apex RTX 5080，沿用[预写协议](PLAN.md)。**结论：本轮不部署。** 幅度规则有实际删尾效果，但无法保证轻声完整；严格数字零规则保留了非零音频，却没有缩短归档的真实异常尾部。

实现：[严格策略与异步包装器](../../../bridge/stream_tail_safe.py)；[测试](../../../bridge/tests/test_tail_safety.py)；[对比脚本](../../../scripts/bench_tail_safety.py)。均独立于生产服务，未被运行 bridge 导入。

## 两种策略的实际取舍

两种策略都在正常EOF后处理长于1秒的段尾，保留300ms；全静音不删、最多暂存256000字节、超限放行。区别是“哪些样本可以视作静音”：

| 策略 | 条件 | 归档结果 | 安全边界 |
| --- | --- | --- | --- |
| 旧幅度 v2 | PCM绝对幅度小于99 | 181条录音的241段中5段触发，合计删25.543秒 | 会删除非零内容；弱声挑战明确失败 |
| 严格候选 | PCM样本恰好为零 | 同一241段零触发、零收益 | 所有非零样本保留；不能删除低幅度非零噪声或模型尾巴 |

181条包含首句36轮、隔离40seed加一次重放，以及两模型104条；各组有重复条件，不估计生产长尾发生率。逐段按原始边界处理，不把整条回答误当成一句。每个文件与代码的哈希见[逐次结果](data/results.json)。旧幅度规则删除的20542个非零样本可能含残余噪声，不能直接全算漏词。

这说明仅靠PCM幅度无法区分“应删的低幅度尾巴”和“应留的轻声词”。严格候选在这批真实音频上没有收益，不通过提高阈值掩盖这个结果。

## 轻声与噪声挑战

取归档0.6B清单的第一条生成音频，提取最后500ms有声区域、减弱后重复三次，再加2秒数字零尾部。它是可精确核对的受控负例，不是天然轻声或真人录音。幅度1的量化会让部分样本变成零，因此两组严格策略的裁剪长度不完全一样。

| 弱尾部峰值 | 幅度v2删除非零样本 | 严格候选删除非零样本 | 严格候选删除时长 |
| --- | ---: | ---: | ---: |
| 70 | 18050 | 0 | 1700ms |
| 1 | 962 | 0 | 1767ms |

严格候选只删尾部数字零，弱尾部的非零PCM样本全部保留。固定种子低幅度噪声尾部的单元测试也逐字节保留。音频对照保留在apex本轮 `audio/weak-peak-*`，不将参考音色或生成音频复制入公开文档。

这证明受测数字样本没有被削掉，不证明主观音质、不证明天然轻声在所有链路中完整。没有请用户回听，本轮也没有获得真人弱声样本。

## 句中停顿与慢流

异步包装器拥有一个上游取包任务，定时等待不取消该任务。已经发送的PCM形成理想播放余量；在余量快耗尽或暂存超过100ms时，原样释放当前静音段并放弃裁剪它，防止一直等EOF。

四个受控实时节拍输入在apex执行：

| 输入 | 输出内容 | 新增理想欠载 |
| --- | --- | ---: |
| 快速到达的有声加2秒零尾部 | 删1.7秒零尾，非零完整 | 0ms |
| 句中零停顿，200ms后恢复轻声 | 全部PCM逐字节相同；超时提前释放 | 0ms |
| 可播放余量不足，300/600ms后续包 | 全部PCM逐字节相同；放行优先 | 约0.079ms |
| 振幅1弱尾后接2秒零尾 | 非零完整，只删数字零 | 0ms |

“新增欠载”是同一来源包时序下两条理想时间轴的差，约0.079ms属于本次事件循环与处理开销；不能写成绝对零开销。纯字节测试还覆盖4秒句中停顿、边界拆包、负极值和溢出。**尚未接真实浏览器扬声器测量。**

## 六条真实HTTP流

用现有生产 `/api/tts/stream` 各请求一次冻结文本，同一流旁路记录原PCM和候选输出，避免两次随机合成混淆差异。没有启动新模型或修改服务。

| 文本 | HTTP到理想首声 | 候选新增首声等待 | 删除时长 |
| --- | ---: | ---: | ---: |
| 你好，我在听。 | 162ms | 0.058ms | 0 |
| 今天先休息吧。 | 478ms | 0.081ms | 0 |
| 你说的是星期四吗？ | 142ms | 0.071ms | 0 |
| 慢慢来，别着急呀。 | 141ms | 0.056ms | 0 |
| 先把文件保存好，然后再关闭窗口。 | 224ms | 0.075ms | 0 |
| 好的，我会等你把话说完。 | 141ms | 0.058ms | 0 |

首声从HTTP请求开始计，到含幅度至少328样本的块到达，再按块内位置估算可播首声；不是用户说完到出声。六条候选的保留内容与原PCM相同，暂存峰值均为零，最多新增理想欠载0.016ms。它们未触发裁剪，不能据此证明有缓存情况下的所有网络行为安全，也不报告p95。

## 插话取消契约

对长文本发起3个自有HTTP请求，分别在首包后50/150/350ms取消消费任务。

| 取消时机 | 取消到本地源关闭 | 取消后新增输出 | 残留缓存 |
| --- | ---: | ---: | ---: |
| 首包后50ms | 0.269ms | 0 | 0字节 |
| 首包后150ms | 0.151ms | 0 | 0字节 |
| 首包后350ms | 0.234ms | 0 | 0字节 |

三条源HTTP响应都关闭，bridge同时记录 `TTS stream cancelled` 和 `cancelled mid-synthesis`，见[结束核验及取消日志摘录](data/postcheck.json)。本地源关闭速度不等于GPU取消耗时。生产取消日志两条标记之间分别约33/18/74ms，仅作为后台实际观察到取消的证据。

这验证保护器可把取消传到现有HTTP合成链路；没有重新测试真实麦克风VAD、浏览器已经排定的音频停止或外放回声。已有插话前端未被修改。单元测试还覆盖持有缓存时取消、消费方提前关闭和上游异常，不在取消时补发旧缓存。

## 决策与下一步

本轮不部署任何裁剪。幅度v2不满足轻声保护；严格零候选满足所测非零样本保留，却无法处理实际发现的非零低幅度长尾。

保留原型和失败对照。若继续推进，需要独立的语音内容证据或生成端终止信息，建立天然弱声负例及回听，再决定是否引入复杂判定；不能仅凭ASR相同或更高的幅度阈值启用裁剪。生产继续使用原链路。

```bash
  --archive ~/voice-ai/experiments \

```

输出目录必须全新；重跑会重新调用6条合成和3条取消实验，应在资源窗口内执行。哈希与逐次数值见[data/results.json](data/results.json)，测试输出见[data/apex-tests.txt](data/apex-tests.txt)。
